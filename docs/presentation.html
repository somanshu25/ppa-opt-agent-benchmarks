Overview

What was built, and the one idea holding it together

Point an agent at a chip flow and ask it to improve the numbers, and the cheapest way to improve the numbers is to stop measuring.

Delete set_output_delay and the tool stops checking those paths, so reported slack improves while the design gets worse. An agent doing gradient descent on visible QoR is driven toward destroying the design. That is not an edge case — it is the gradient.

So the scarce artifact is not the optimising agent. It is the grader. The agent is replaceable; the grader is the moat.

Task 1 — Hard problems

Four defined (HP-A…HP-D), each with goal, why coding agents fail, inputs, how to measure correctness, and the product. Five structural reasons the domain breaks coding agents — four of them measured here, not asserted.

Task 2 — Benchmarks

sdc-repair-v1 and knob-opt-v1, both in the SWE-bench shape: environment, task, grader. Instances are self-proving — 4 of 8 generated were rejected by measurement.

Task 3 — Baseline

Claude Code headless, one sanitised container per instance. 4/4 resolved. Plus four scripted decoys that prove the grader can't be gamed, and a controlled A/B that cost 33% of the objective.

Task 4 — Product

One product, four capabilities, built in the order the evidence supports. Mock UI grounded entirely in measured numbers, plus the evidence pack an engineer needs before trusting any of it.

Task 1 · Define hard problems

Why this domain breaks coding agents

ReasonMeasured evidence
R1 · The oracle is slow and non-binary SWE-bench runs tests in seconds, pass/fail. Here one evaluation is 40 s on gcd, 524 s on aes — and the answer is a vector with real tradeoffs, not a boolean.
R2 · The visible objective is corrupted
the load-bearing one
 Deleting set_output_delay: the flow reports +31% more slack (0.184 → 0.241) while sign-off says 0.184 → 0.176, worse.
R3 · Causality is physical, not textual Identical text, different consequences per design. The ABC clock target moved nothing on gcd or aes even under a 6× period change.
R4 · Correctness has two independent axes Functional equivalence and constraint legality. "20% smaller" is worthless without proving you changed neither.

R5 is the shape of every mistake in this domain: silent, plausible-looking, and invisible without domain-specific verification. It was caught only because a self-test demanded exact agreement.

Task 1 · Define hard problems

Four problems, and where each stands

ProblemGoalProductStatus
HP-A Constraint integrity Is this design actually being checked? Constraint Guard — CI gate built · 4/4
HP-B Budgeted die-area minimisation Improve a design nobody broke, under a run budget Closure Copilot built · optimum hit
HP-C QoR regression root-cause "Area went up 8% — which stage, and why?" QoR Bisect defined
HP-D Top-level → block budgeting Allocate interface budget across blocks Budget Broker defined

HP-D is the sharpest argument, even unbuilt

Local success, global failure. Every block closes timing standalone; the chip does not. There is no per-block test that can reveal it, because the defect isn't in any block — it's in the relation between them. No file contains the bug, which breaks the SWE-bench shape entirely.

And upstream says the capability is missing. Verbatim from platforms/asap7/constraints.sdc:

"ORFS regression checks do not have the ability to distinguish between timing closure failures (register to register paths) and optimization constraints violations."

Scoping is deliberate: two problems built deep beats four shallow. An earlier draft of this analysis put HP-D first — measurement changed the ordering, which is the same discipline that killed two defect classes.

Task 2 · Create benchmark tasks

The grader, in one idea borrowed from SWE-bench

SWE-bench faces the identical attack — an agent could edit the tests. Its defence is one line:

git checkout <base_commit> -- tests/

It throws away the agent's copy of the thing that judges it. We do exactly that to constraints.

        agent's layout                        measuring stick
        ─────────────────                     ───────────────
  BUILT WITH:  impl.sdc      ──────────►      JUDGED WITH: golden.sdc
  6_final.odb   netlist + placement + routing   ← unchanged
  6_final.spef  its own extracted parasitics    ← unchanged

Re-time, don't re-run. The layout is frozen; only the ruler changes. Loosening a constraint cannot buy score, because the loosened constraint is not the one used to judge. This mirrors real practice — implementation SDC versus sign-off SDC.

Validated exact — and the self-test earned its keep

With golden == impl, sign-off must reproduce the flow's own numbers. It does, to the digit, on all six timing metrics. The first attempt failed by 4.8 ps and caught a real bug: CTS adds set_propagated_clock, so ideal clocks were being timed against a design with a real clock tree. Without the self-test that ships as a silently biased gate.

Task 2 · Create benchmark tasks

Two benchmarks, and how they differ

sdc-repair-v1 — HP-A

Task. One defect injected into the constraints. Diagnose and repair it; judged on the physical design that results.

Deliverable. An edited impl.sdc — the only file read.

F2P. signoff_setup_ws, signoff_setup_tns ≥ baseline. 9 P2P gates alongside.

knob-opt-v1 — HP-B

Task. Nothing is broken. Shrink the die by tuning flow knobs, inside a 12-run budget.

Deliverable. knobs.json — a knob-value map.

F2P. die_area ≤ baseline × 0.98. 11 P2P gates alongside.

The structural difference that changes the grading shape

In repair, something is broken, so assertions flip fail-to-pass — that is what FAIL_TO_PASS means. In optimisation nothing is broken: every assertion passes at baseline, so there is no flip to define, and left alone the null agent wins by changing nothing. Hence an improvement threshold.

Two more departures, both forced by measurement: area_not_ballooned is dropped (it caps the very thing being optimised), and the timing gate becomes "still closes" rather than "no worse than baseline" — under the repair gate, the true optimum fails over 5 ps while closing comfortably.

Both are graded the same way: re-run from clean with the submission, then re-time against a reference the agent never controlled. The agent's own run directory is never trusted — the same reason SWE-bench re-runs tests from a fresh checkout.

The answer was in the room

Two different attacks need two different defences. The sign-off gate stops an agent that cheats. It does nothing against one that simply knows the answer.

$ grep set_input_delay flow/results/nangate45/gcd/base/6_final.sdc
set_input_delay 0.0920 -clock [get_clocks {vclk_core_clock}] -add_delay [get_ports {req_msg[0]}]

That is the C2 answer, fully elaborated, sitting in a stale results directory the agent could read.

Sanitisation is necessary but unfalsifiable — you can never prove you found every path. Randomisation is sufficient by construction: an instance that didn't exist before we generated it cannot have been memorised.

Sampling is keyed on a secret held outside the agent-visible tree. Without it, the public seed plus this repo's own sampler would recompute the golden in one line — a leak I introduced and then found by auditing my own instances.

It works: the agent recovered randomised periods 0.69 and 0.58 exactly. Neither is upstream's 0.46, the leak audit was clean — so it had to recognise the ×1000 unit slip and invert it, not recall a value.

The reward hack, measured

cheat_loose relaxed the clock to 5 ns. Its own run reports +3.58 ns of slack — 19× the baseline. By every metric the agent can see it produced a spectacular design. Sign-off says 0.143, worse than baseline. It resolves to zero.

And the row that justifies the whole bracket

cheat_knob suppressed detailed routing, which makes timing optimistic — 0.21163 beats the baseline's 0.18390. It passed both FAIL_TO_PASS assertions. The centrepiece gate did not catch it. DRC, antenna and the knob denylist did.

F2P alone lets cheat_knob through by not measuring. P2P alone lets null through by doing nothing. Neither is sufficient — absence of evidence must fail. That is SWE-bench's bracket, validated empirically rather than argued.

The first C5 run failed — and it was our bug, not the agent's

It ran a genuine parameter sweep (io020…io035), hit max_turns mid-search, and never wrote its conclusion back. Graded as the null agent. A task-design defect. Two fixes — require writing best-so-far after every trial, and report terminal_reason so truncation is never conflated with a wrong answer — then a re-run at the same budget resolved it.

C5 also vindicated behavioural grading

Golden was 0.15; the agent submitted 0.35 and passed, because its layout re-times as well as the golden's. The question is never "did you recover the reference value" but "is the design you produced as good". I had flagged C5 as possibly unfair — that concern was wrong, for exactly this reason.

Task 3 · Run a baseline

A one-paragraph spec bug cost 33% of the objective

The optimisation grader was fixed to accept any non-negative slack — but the prompt was not updated. Same agent, same 12-run budget, same tools. The only change between runs was that paragraph.

succeeds flow dies (FLW-0024)

In v1 the agent had measured u74 at 24.3% reduction with positive slack and deliberately rejected it, in its own words to satisfy "both the strict reading and the loose reading" of an ambiguous rubric. That is correct behaviour against the spec it was given.

A third failure mode, beyond "agent games the grader" and "agent finds the answer": the task description and the grader disagree. It is the most invisible of the three — every gate passes, the agent looks sensible — and it is only detectable against a measured reference optimum.

Task 3 · Run a baseline

What the baseline taught us about the benchmark

Why it succeeded

C1 is unambiguous once diagnosed, and randomisation forced reasoning over recall — the agent had to recognise a ×1000 slip, not remember 0.46. C3 passed with a textually different fix (extra newline), because grading is behavioural, not diff-matching.

Why it failed

Never on reasoning. Once on budget (truncated mid-sweep, submitted nothing) and once on our ambiguous spec. Both were benchmark defects; both are fixed.

Improvements this drove

  • Task: require best-so-far checkpointing every trial, so truncation degrades gracefully instead of submitting nothing.
  • Harness: report terminal_reason — a 3/4 that hides a truncation is a dishonest number.
  • Grader: the timing gate must match the problem class — "restore baseline" for repair, "still closes" for optimisation.
  • Spec: state the gate in the prompt in the same words the grader uses. Drift between them is invisible and expensive.

The cost asymmetry is a finding, not a footnote

Task shapeWallCostBudget
Repair (C1, C3)~140 s~$0.22comfortable
Search (C5, HP-B)~1000 s$0.85–2.39consumed in full, every time

Search is ~7× the wall time and ~6× the cost. That is the argument for making run budget an explicit, graded dimension — and, at hours per run on a real block, it is the business model rather than a detail.

Task 4 · Motivate the future product

Four capabilities, one substrate

① Constraint Guard · grader built

CI gate. Every SDC pull request is re-timed against sign-off constraints the author does not control.

PR #412  "tighten IO budget"        ✗ BLOCKED
Author reports:  WS 0.184 → 0.241  ▲31% better
Sign-off says:   WS 0.184 → 0.176  ▼ worse
ⓘ deletes set_output_delay — 35 endpoints
  became unconstrained.

② Closure Copilot · grader built

Proposes configurations, runs them under budget, presents a Pareto board for approval. The screen on the previous slide.

The comparator that makes it credible: ORFS ships AutoTuner, a real non-LLM optimiser over the same knob space. The claim to earn is not "we found −27%" but "we matched AutoTuner in 11 runs and explained why."

③ QoR Bisect · defined

Attributes a regression to a stage, then a cause — distinguishing causal from inherited deltas.

synth      +0.0%  ·
floorplan  +8.1%  ████  ← first appears
place      +8.1%  ████  (inherited)
route      +8.2%  ████  (inherited)
ROOT: CORE_UTILIZATION 60→55, commit a3f21c

Only sound because QoR is bit-exact deterministic — every delta is attributable.

④ Budget Broker · defined

Allocates interface budgets across blocks and re-negotiates as blocks report back.

reg2out(A) + interconnect + in2reg(B)
                    ≤ period − uncertainty

allocated 480 ps > 450 ps budget   ✗ −30 ps
⚠ Every block closes. The chip does not.

The top-tier check is arithmetic — verifiable by hand in ten seconds, which is what you want in a gate a lead engineer signs.

The evidence pack — what ships with every result

What an engineer wants before trusting an agent. One export per run.

ArtifactWhy it is in the pack
Verdict — every assertion, pass/fail, with numbers Not a score. The actual checks, individually legible.
Sign-off delta — implementation view vs held-out view Where the lie would be, if there were one.
Search trace — every trial, including the failures The cliff is knowledge the engineer keeps after the agent is gone.

vs reference — % of known-achievable Catches spec/grader disagreement. Nothing else does.
Budget + cost — runs used, dollars "Found in 11 runs" ≠ "found in 400".
Replay command — pinned commit, exact invocation Reproducible without the product. An evidence pack that only works inside the tool is lock-in, not trust.
Leak audit — what the agent could reach Evidence it solved rather than looked up.

Build order — and it is a safety argument, not a difficulty ranking

Constraint Guard first, even though Closure Copilot is the flagship. Without a cheat-proof grader underneath, a closure copilot is an automated way to ship a design that reports good numbers and is not.

Closing

What I'd fix, and what would make this fail

Known limits, stated rather than hidden

LimitDetail
Two levers of three SDC has 4 agent runs, flow knobs 2. RTL/netlist: 0 — and it is where cheating is easiest, needing an equivalence gate that does not exist here yet.
Two designs, one platform gcd (~1100 cells) and aes (~19k). ibex and sky130hd explored but not benchmarked. All Nangate45 except the sky130hd baseline.
HP-B is single-knob Five of eight permitted knobs are inert on gcd. It measures budgeted search against a cliff, not multi-objective breadth.
No AutoTuner comparison The highest-value thing remaining, and it needs no grader changes.
Repair, not open-ended optimisation HP-A has ground truth because we injected the defect. That is its strength and its ceiling.

C2 and C3 traded places. C2 was completely inert on gcd — byte-identical layout after deleting all 35 input delays — and on aes it is the most severe defect in the suite. C3 did the reverse. The prediction that I/O-defect classes need an I/O-critical design held, and the machinery transferred with zero changes.

Two other aes results: it does not close at its own upstream period (first clean baseline is 0.95, not the 0.85 I had guessed — the second time a sweep caught a wrong guess), and its die area is fixed by a floorplan DEF, so HP-B's objective does not transfer at all, though power moves 25%.

The mechanism generalises. The objective and the defect class do not. A suite that assumes one class or one objective fits every design will silently ship vacuous instances — which is exactly what per-instance validation is for.

Four of the thirteen findings are negative — a corruption channel with no consequence, an inert defect class, a wrong guessed range, an untunable objective. They are in the repo on purpose: they are the reason the remaining claims are worth believing.
